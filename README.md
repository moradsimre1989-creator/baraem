# براعم — منصّة الوحدات التعليمية (وحدة الزيتونة)

تطبيق ويب (React + Tailwind CSS) لطلاب الصفّين الثاني والثالث في مدرسة النجاح الابتدائية. الاسم العام
للمنصّة هو **براعم**، وهي مصمَّمة لتحتضن أكثر من وحدة تعليمية بمرور الوقت (تماماً كما كل غصن في
هذه الوحدة = مجال دراسي، أي وحدة قادمة قد تستخدم نفس فكرة "المحتوى كشجرة"). **وحدة الزيتونة**
هي أول وحدة مبنية على المنصّة، وهي الوحدة الوحيدة الموجودة حالياً.

لا يوجد تسجيل دخول — الطالب يدخل مباشرة إلى شجرة المحطات، وتقدّمه يُحفظ محلياً في متصفحه
(`localStorage`) تلقائياً.

## الحالة الحالية

**الوحدة كاملة بمراحلها الأربع (أ، ب، ج، د جزئياً):**

- الهيكل العام، الخريطة (شجرة المحطات)، ومحرك الفعاليات العام.
- **11 محطة كاملة** بمحتوى فعلي (لا محتوى مُختلَق): اللغة العربية، اللغة العبرية
  والإنجليزية، الرياضيات، موطن، دين، التعلّم الاجتماعي–العاطفي، اقتصاد، علوم، موسيقى، فنون،
  ورياضة — **198 نشاطاً** بـ**24 نوع فعالية**، وأقلّ محطة فيها 6 أنشطة.
- **مساران للمحتوى نفسه**: شجرة المواد (كما كانت تماماً)، و**مسار الزيتونة** الموضوعي
  بـ14 محطة تعيد ترتيب الأنشطة نفسها بحسب الموضوع لا بحسب المادة. التقدّم مشترك بين
  المسارين لأنه محفوظ بمعرّف النشاط، فإنجاز نشاط في أحدهما يظهر في الآخر فوراً.
- **مستويان: الصف الثاني والثالث** — يُختاران في أول زيارة ويُبدَّلان من الشريط العلوي.
  النشاط الذي يحمل حقل `grade` يظهر لصفّه وحده، وما لا يحمله يظهر للصفّين معاً.
- **مسار بيداغوجي ثماني** داخل كل محطة موضوعية: أكتشف ← أستمع وأشاهد ← أفهم ← أتدرّب ←
  أطبّق ← أتحدّى نفسي ← أقيّم تعلّمي ← أنجزت (بشارة المحطة ونتيجتها).
- شاشة تلخيص وإجمال بتقييم ذاتي لكل محطة.
- **مساعد المعلّمة 🤖**: زر عائم في كل شاشة يفتح مساعداً إرشادياً يجيب على أسئلة شائعة عن
  استخدام التطبيق (إضافة وحدة، النقاط، إعادة الضبط...). **هذا مساعد قائم على قواعد داخل
  التطبيق نفسه (بدون اتصال بالإنترنت أو تكلفة) وليس ذكاءً اصطناعياً حقيقياً متصلاً بخدمة
  خارجية** — إن أردتم مساعداً بذكاء اصطناعي حقيقي لاحقاً، هذا يتطلب مفتاح API وخدمة مدفوعة،
  وهو قرار منفصل يستحق نقاشاً بخصوص التكلفة والخصوصية.

**لم يُبنَ بعد (يحتاج قراراً بخصوص الأولوية):**
- لوحة المعلّمة الفعلية (بكلمة مرور، لعرض إجابات الطلاب المفتوحة وتصدير النتائج).
- شهادة الإنجاز القابلة للطباعة وأزرار طباعة أوراق العمل.

**يحتاج مراجعتكم قبل الاستعمال في الصف:**
- **تراخيص الصور غير موثّقة.** الصور الـ23 حقيقية وعالية الجودة وبلا علامات مائية، لكننا لا
  نملك سجلّ مصادرها. الحقول في `src/data/photoCredits.js` مُعلَّمة `null` عمداً بدل ملئها
  بقيم مفترَضة — ادّعاء ترخيص غير محقَّق أسوأ من الاعتراف بأنه غير موثّق. راجعوا المصادر
  واملأوا الحقول قبل أي نشر خارج المدرسة.
- **المحتوى المُضاف حديثاً** (أنشطة الفنون والرياضة والاقتصاد والدين والتعلّم الاجتماعي
  الجديدة، وأنشطة الصف الثالث) كُتب ضمن هذا التطوير ولم يمرّ بعد على مراجعة معلّمة.

## التشغيل

```bash
npm install
npm run dev
```

افتح الرابط الذي يظهر (عادة `http://localhost:5173`).

للبناء للإنتاج: `npm run build` (الناتج في مجلد `dist/`، يمكن رفعه على أي استضافة ثابتة).

## بنية المشروع

```
src/
  data/units/zaytouna.js     ← كل محتوى وحدة الزيتونة (النص، المحطات الإحدى عشرة، الفعاليات)
  data/units/zaytounaPath.js ← مسار الزيتونة الموضوعي: 14 محطة تشير إلى الأنشطة بمعرّفاتها
  data/photoCredits.js       ← الوصف البديل العربي لكل صورة + مصدرها وترخيصها
  data/teacherFaq.js         ← قاعدة أسئلة وأجوبة مساعد المعلّمة
  context/GradeContext.jsx   ← اختيار الصف (الثاني/الثالث) وتصفية الأنشطة بحسبه
  components/                ← الشاشات: الخريطة، المحطة، الفعالية، التلخيص، مساعد المعلّمة
  components/activities/     ← مكوّن لكل نوع فعالية + المحرك العام (ActivityRenderer)
  components/ui/             ← عناصر مشتركة (أزرار، تغذية راجعة، زر استماع، صورة غلاف)
  hooks/useProgress.js       ← حفظ التقدّم والنقاط والشارات في localStorage
  utils/speech.js            ← النطق الصوتي بأي لغة (Web Speech API) والتسجيل (MediaRecorder)
  utils/sound.js             ← نغمات التغذية الراجعة (مولَّدة، بلا ملفات صوت)
scripts/to-webp.mjs          ← تحويل صور الوحدة إلى WebP (يُشغَّل عند إضافة صور جديدة)
```

## كيف أضيف وحدة (موضوع) جديدة إلى براعم؟

1. أنشئ ملفاً جديداً `src/data/units/<اسم-الوحدة>.js` بنفس شكل `zaytouna.js`:
   `id`, `title`, `year`, `grade`, `school`, `coverEmoji`, `text`, و`domains` (مصفوفة مجالات، كل
   مجال فيه `activities`).
2. كل فعالية هي كائن: `{ id, type, title, points, data }`، ويقبل اختيارياً `skill` و`grade`
   (2 أو 3؛ بدونه يظهر النشاط للصفّين). الأنواع المدعومة حالياً (24 نوعاً):
   `read`, `memorize`, `mindmap`, `match`, `mcq`, `trueFalse`, `dragToBlank`, `open`, `sort`,
   `wordBuild`, `order`, `math`, `numberBuild`, `trilingual`, `draw`, `outdoor`, `memory`,
   `hotspot`, `facts`, `shadowSim`, `story`, `video`, `findWord`, `randomPrompt`
   (راجع `zaytouna.js` كأمثلة فعلية على شكل `data` لكل نوع).
3. لإضافة نوع فعالية جديد غير موجود: أنشئ مكوّناً في `src/components/activities/` بنفس الواجهة
   `({ activity, onComplete }) => ...` وسجّله في `REGISTRY` داخل `ActivityRenderer.jsx`.
4. لعرض وحدة أخرى بدل الزيتونة، أو لإضافة شاشة اختيار بين عدة وحدات: غيّر/وسّع الاستيراد
   `import { unit } from "./data/units/zaytouna.js"` في `App.jsx` و`TreeMap.jsx`
   و`ReadActivity.jsx` — هذه هي النقطة الوحيدة التي تحتاج تعميماً عند إضافة أكثر من وحدة واحدة
   للمنصّة (غير مطلوب حالياً لأن الزيتونة هي الوحدة الوحيدة).

لا حاجة لتعديل أي شاشة أخرى — الواجهة عامة بالكامل وتعمل مع أي وحدة بنفس السكيما.

## قرارات تصميم يستحق مراجعتها معكم

- الألوان والخط الحالي (Noto Naskh Arabic / Amiri) هما اختيار أوّلي، قابلان للتغيير بالكامل عبر
  `src/index.css` (متغيّرات `@theme`) لو أردتم هوية بصرية مختلفة للمنصّة.
- مساعد المعلّمة حالياً قائم على قواعد ثابتة (بدون تكلفة). لو أردتم نسخة بذكاء اصطناعي حقيقي
  تفهم أسئلة حرة، هذا قرار منفصل يحتاج مفتاح API لخدمة كـ Claude، وتكلفة تشغيل مستمرة.

## كيف أضيف محطة إلى مسار الزيتونة الموضوعي؟

المسار طبقة عرض فقط: لا يحمل محتوى، بل يشير إلى أنشطة موجودة في `zaytouna.js` بمعرّفاتها.
افتح `src/data/units/zaytounaPath.js` وأضف كائن محطة إلى `stations`:

```js
{
  id: "my-station",
  title: "عنوان المحطة",
  icon: "🌳",
  cover: myPhoto,                       // استوردها من src/assets/photos/
  description: "سطر واحد يشرح المحطة.",
  badge: { emoji: "🏅", label: "اسم الشارة" },
  steps: {                              // معرّف المرحلة ← قائمة "domainId/activityId"
    discover: ["science/senses-mcq"],
    understand: ["arabic/comp-where-1"],
  },
}
```

المراحل الثماني معرّفة في `PHASES` أعلى الملف. المرحلة الفارغة لا تُعرض للطالب.
النشاط نفسه قد يظهر في أكثر من محطة موضوعية حين يخدم الموضوعين — والتقدّم يبقى واحداً.

## إضافة صور جديدة

1. ضع ملف `.jpg` في `src/assets/photos/`.
2. شغّل `node scripts/to-webp.mjs` (يولّد `.webp` بجانبه ويحتفظ بالأصل).
3. أضف مدخلاً في `src/data/photoCredits.js` بالوصف البديل العربي والمصدر والترخيص.
4. استورد نسخة `.webp` في `zaytouna.js` أو `zaytounaPath.js`.

الحزمة تضمّن الصور داخلها (`assetsInlineLimit` في `vite.config.js`) حتى تبقى نسخة الـ Artifact
ملفاً واحداً يعمل بلا خادم — لذلك حجم الصور يؤثّر مباشرة في حجم الحزمة، وWebP ضروري لا تحسين
اختياري.

## الوصولية

- الواجهة كاملة من اليمين إلى اليسار (`direction: rtl`).
- جذر الصفحة 18px على الهاتف و20px على اللوح و21px على الحاسوب، فتكبر كل الأحجام والمسافات
  معاً بنفس النسبة (نص 20-24px، عناوين أقسام 26-32px، عنوان رئيسي 34-40px).
- كل عنصر تفاعلي ارتفاعه 44px على الأقل، وله حلقة تركيز واضحة للتنقّل بلوحة المفاتيح.
- نشاط «سحب الكلمات» يعمل بالنقر وبلوحة المفاتيح كاملاً؛ السحب بالفأرة تحسين فوقه لا شرط له.
- زر استماع بالعربية بجانب النصوص والأسئلة (Web Speech API، بلا إنترنت وبلا تكلفة).
- كل صورة لها وصف بديل عربي من `photoCredits.js`، والصور غير الظاهرة على الشاشة تُحمّل كسولاً.

## الموقع والنشر

الموقع الحيّ: **https://moradsimre1989-creator.github.io/baraem/**
المستودع: **https://github.com/moradsimre1989-creator/baraem**

- `main` يحمل الكود، و`gh-pages` يحمل **ناتج البناء فقط** وهو ما تخدمه GitHub Pages.
- لنشر أي تعديل: `npm run deploy` — يبني بالمسار الفرعي `/baraem/` ويدفع الناتج،
  والموقع يتحدّث خلال دقيقة تقريباً.
- اسم المستودع `baraem` هو ما يحدّد المسار الفرعي. تغييره يستوجب تغيير `BASE` في
  `scripts/deploy.mjs` معاً، وإلا انكسر كل رابط أصل في الموقع.

### لتفعيل النشر التلقائي الكامل (بلا `npm run deploy`)

ملف GitHub Actions جاهز في `.github/pages-deploy.workflow.yml` — موضوع **خارج**
`.github/workflows/` عمداً، لأن توكن `gh` الحالي بلا صلاحية `workflow` فلا يستطيع رفع
أي ملف داخل ذلك المجلد. مرة واحدة فقط:

```bash
gh auth refresh -s workflow      # يفتح المتصفح لمنح الصلاحية
mkdir -p .github/workflows
cp .github/pages-deploy.workflow.yml .github/workflows/deploy.yml
git add .github/workflows/deploy.yml && git commit -m "نشر تلقائي" && git push
```

بعدها كل `git push` إلى `main` يبني الموقع وينشره وحده، ولا حاجة لأي أمر نشر.
